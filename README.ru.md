# GitHub Folder Sync

[Read in English](README.md)

Графическая утилита для Windows и Linux, которая сравнивает локальные папки с репозиториями GitHub. В одной таблице видно, где есть репозиторий, совпадают ли коммиты в ветках и можно ли скачать обновления или клонировать репозиторий.

## Скачать и запустить

Скачайте архив для своей системы со страницы [GitHub Releases](https://github.com/Ruslan-Shevyrev/github-folder-sync/releases) и распакуйте его целиком.

- **Windows x64** — распакуйте `GitHubFolderSync-{VERSION}-windows-x64.zip` и откройте `GitHubFolderSync.exe`.
- **Linux x86-64** — распакуйте `GitHubFolderSync-{VERSION}-linux-x86_64.tar.gz` командой `tar -xzf` и запустите `./GitHubFolderSync/GitHubFolderSync` из каталога распаковки в графической сессии. Для открытия локальных папок используется `xdg-open`.

В готовые сборки уже входит Python. Для проверки веток и операций с репозиториями нужен Git в `PATH`.

## Как пользоваться

1. Нажмите **«Добавить пользователя»**, сохраните логин GitHub и выберите пользователя в списке.
2. Выберите **локальную папку** через **«Обзор…»** или введите путь вручную. Программа сравнит имена её непосредственных подпапок с именами репозиториев без учёта регистра.
3. Нажмите **«Сравнить»**. Таблица покажет, где есть репозиторий, какова его видимость на GitHub и в каком состоянии ветки. Флажок **«Требуют внимания»** оставит строки с отсутствующими репозиториями, расхождениями веток или ошибками.
4. Нажмите **«Сохранить как профиль»**, чтобы запомнить папку и пользователя. Профиль с отметкой по умолчанию загружается при запуске. Сохранённые записи можно менять через **«Просмотр пользователей»** и **«Просмотр профилей»**.

В правом верхнем углу можно выбрать русский или английский язык и тему **Dark** или **Light**. Программа запоминает оба выбора. При первом запуске открывается тёмная тема.

## Ветки и действия в строке

- **Зелёный** означает, что ветка указывает на один и тот же коммит с обеих сторон. **Красным** отмечается отстающая сторона. **Жёлтым** — опережающая или единственная. **Серый** означает, что ветки разошлись или доступна только часть истории.
- **↻** обновляет одну строку. **↓** клонирует отсутствующий репозиторий, создаёт отсутствующую локальную ветку или обновляет отстающую ветку через `git pull --ff-only`. Перед обновлением переключитесь на нужную ветку и сохраните изменения в рабочей папке. Стрелки в колонке «Ветки» показывают направление синхронизации.
- **Корзина** безвозвратно удаляет локальную папку и её содержимое после подтверждения.
- Щелчок по пути открывает папку в системном файловом менеджере, а по ссылке — репозиторий в браузере. Если `origin` ведёт на другой репозиторий, щёлкните по сообщению, чтобы увидеть текущий адрес и подтвердить исправление.

## Приватные репозитории

Публичные репозитории доступны без токена. Для доступа к приватным добавьте fine-grained Personal Access Token к сохранённому пользователю. Выберите нужные репозитории и задайте право **Contents: Read** для проверки веток, клонирования и обновления.

Можно ввести токен напрямую или указать `v{VARIABLE_NAME}`, чтобы прочитать его из переменной окружения. Токен, введённый напрямую, сохраняется открытым текстом в локальном файле настроек. При использовании переменной сохраняется только ссылка на неё. Все профили одного пользователя используют его токен.

## Настройки и кэш

Программа хранит настройки в `settings/settings.json`, а последнее сравнение каждого профиля — в `cache/`. Обе папки создаются рядом с исполняемым файлом или в корне проекта при запуске из исходников. Если запись туда недоступна, программа использует те же подпапки в `%LOCALAPPDATA%\GitHubFolderSync` на Windows или в `$XDG_DATA_HOME/GitHubFolderSync` на Linux. Путь по умолчанию на Linux — `~/.local/share/GitHubFolderSync`. Git игнорирует обе папки в проекте.

При выборе профиля с сохранённым результатом таблица открывается сразу, с пометкой **«Данные из кэша»**. Кнопка **«Сравнить»** загружает свежие данные. Фильтр **«Требуют внимания»** работает с уже открытой таблицей без обращения к GitHub.

## Запуск из исходников

Выполните команды для своей системы из корня проекта. Нужны Python 3.13 или новее и Tkinter.

### Windows

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe github_folder_sync.py
```

### Linux

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python github_folder_sync.py
```

Интерфейс использует CustomTkinter, а для сравнения веток и операций с репозиториями программа вызывает системный Git.

## Сборка для Windows x64

Для сборки нужен 64-битный Python. Скрипт установит зависимости в `.venv` и соберёт переносимую версию через PyInstaller.

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
.\dist\GitHubFolderSync\GitHubFolderSync.exe
```

Чтобы создать ZIP для распространения, выполните команду:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Zip -Version v{VERSION}
```

Архив появится по пути `dist/GitHubFolderSync-v{VERSION}-windows-x64.zip`.

## Сборка для Linux x86-64

Запустите сборку из корня проекта на Linux x86-64 с Python 3.13 или новее, Tkinter и `venv`.

```bash
bash ./build.sh v{VERSION}
```

Скрипт установит зависимости в `.venv` и создаст `dist/GitHubFolderSync-v{VERSION}-linux-x86_64.tar.gz`. При запуске `bash ./build.sh` без аргумента версия в имени архива будет `local`.
